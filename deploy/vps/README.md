# Overman: установка закрытой беты на VPS

Владелец: Petr Stekliannikov. Версия Android: 0.4.45 (48).

Пакет содержит веб-приложение, Go API, PostgreSQL, HTTPS-прокси и подписанный APK. Это подготовка к публикации; наличие пакета не означает, что публичный сервер уже работает. Docker Compose проверен синтаксически; полный запуск Linux-контейнеров и публичный HTTPS ещё предстоит проверить на выбранном VPS.

## Что подготовить

- Отдельный VPS: x86-64, Ubuntu 24.04 LTS, 2 vCPU, 4 GB RAM, от 40 GB SSD. Это стартовая конфигурация для небольшой беты, нагрузочное испытание не проводилось.
- Docker Engine с Compose v2, OpenSSL, curl, util-linux (flock). Установка Docker: https://docs.docker.com/engine/install/ubuntu/ . Подойдёт образ провайдера с уже установленным Docker.
- Домен или поддомен с A-записью на IPv4 VPS. Если есть AAAA, она также должна вести на этот сервер. Входящие TCP 80 и 443 открыты; SSH доступен владельцу по ключу. База и API наружу не открываются.
- Самостоятельно оплатить выбранный тариф. Покупок от имени владельца этот пакет не выполняет.

Бесплатный Render усыпляет сервис после 15 минут без запросов, а бесплатная PostgreSQL там истекает через 30 дней; для постоянной беты предпочтителен VPS. Источник: https://render.com/docs/free .

## Установка

Распаковать выпуск в новый каталог `/opt/overman`. Не копировать сюда локальные `.tools`, тестовые базы, сохранения телефона, файлы окружения и ключи разработчика. Проверить SHA-256 файлов по `release-manifest.json`.

```sh
cd /opt/overman/deploy/vps
cp .env.example .env
# В .env указать OVERMAN_DOMAIN=реальный-домен
sudo bash install.sh
```

Сценарий создаёт новые случайные пароли только при первой установке. Не публикует их, не заменяет существующие секреты; неполную первоначальную настройку оставляет для проверки владельцем. Применяет миграции с контролем SHA-256, перед обновлением существующей базы создаёт резервную копию. Изменённая ранее применённая миграция останавливает установку. Открываются `https://домен/` и `https://домен/downloads/overman.apk`; HTTPS выпускает Caddy. В первый запуск нужно дождаться загрузки образов и сборки.

APK в этом выпуске позволяет указать HTTPS-адрес сервера в профиле. После выбора окончательного домена можно выпустить установщик с адресом по умолчанию. Будильник работает в Android-приложении; сайт не заменяет системный будильник.

## Проверка перед приглашением пользователей

1. Открыть `/health`: должны быть Go и PostgreSQL. Убедиться, что обычный HTTP перенаправляется на HTTPS, сертификат действителен.
2. Создать два отдельных тестовых аккаунта в разных браузерах/Android. Добавить друг друга по коду и принять запрос. Время сна и прогресс изначально закрыты.
3. Явно отправить одну тестовую запись на сервер. Открыть другу только время сна, затем отдельно прогресс. Отозвать время сна и обновить второй клиент: часы должны исчезнуть, разрешённый прогресс остаться. Проверить удаление дружбы с обеих сторон.
4. Скачать APK, проверить SHA-256 по манифесту, установить обновлением без удаления приложения. Убедиться, что прежние записи остались. Проверить сервер из мобильной сети, а не только с VPS.
5. Убедиться, что `/api/dev-capture` и прочие старые `/api/*` отвечают 404. Снаружи отсутствует доступ к портам PostgreSQL и API.

До этих проверок публикацию нельзя считать завершённой. Реальные сообщения друзьям автоматически не отправляются. Видны только явно синхронизированные записи; личные заметки, самооценки и данные Health Connect друзьям не раскрываются. Автоматический индекс сна экспериментальный и не является клиническим измерением.

## Обновления и резервные копии

```sh
cd /opt/overman/deploy/vps
sudo bash backup.sh
sudo bash install.sh
docker compose ps
```

Сохранять `.env`, `secrets/`, PostgreSQL volume и Caddy volumes. Не выполнять `docker compose down -v`. Пароли, дампы и весь каталог `secrets/` не пересылать в чат. Резервные копии содержат личные данные; хранить закрыто, дополнительно выносить на отдельное защищённое хранилище. Автоматическая удалённая копия этим выпуском не настроена. Перед восстановлением остановить API/веб и проверить выбранную копию; не накатывать дамп поверх работающей пользовательской базы.

При неудачной миграции дальнейшее обновление останавливается; текущие данные не удалять. Возврат старого приложения не откатывает схему базы: совместимость проверять отдельно, восстановление из копии выполнять осознанно.

Таймер не измеряет внимание; завершённый сеанс подтверждает пользователь. Физический телефон и ограничения конкретного производителя требуют отдельной проверки.

Удаление обязательной дружбы скрывает группу. Проверить приглашение/принятие/отказ в двух клиентах на публичном сервере; эти изменения требуют миграции017. Приглашения обновляются при открытом профиле, фоновые push-уведомления ещё не настроены. Кнопка не является доказательством, что участники легли спать.
